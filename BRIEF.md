# BRIEF — mercurius-peer

Клиентская сторона связи агентов по A2A v1.0 для AMPHP v3: агента узнают по ключу ECDSA P-256, а не по общему
токену. Клиент берёт карточку соседа и проверяет, что она доказывает свой ключ, отправляет задачу, спрашивает её
состояние, отменяет её и передаёт файлы раньше сообщения — по одному WebSocket с рукопожатием обоих ключей или по
HTTP с подписью каждого запроса. Пакет — часть Меркурия (`opencck/mercurius-peer`, пространство имён
`Mercurius\Peer`), но от приложения не зависит: только `amphp/amp`, `amphp/http-client` v5 и `ext-openssl`.

## Назначение и границы

В пакете:

- ключ агента: создание, чтение из PEM, подпись, проверка, отпечаток, и точный состав данных каждой подписи;
- клиент A2A: карточка с доказательством ключа, `SendMessage`, `GetTask`, `CancelTask`, выгрузка и загрузка файлов;
- соединение JSON-RPC поверх канала после рукопожатия ключей: запросы в обе стороны и уведомления;
- реестр живых соединений в обе стороны;
- общее для обеих сторон: коды ошибок входа, пределы файлов, схема ссылок `a2a-file:`, multipart.

В приложении остаётся то, что зависит от его участников, политик и агентского цикла:

- сервер A2A (`A2aServer`): карточка, `POST /a2a`, вход WebSocket, `POST`/`GET /a2a/files`, проверка подписей
  входящих запросов, лимиты и идемпотентность;
- `PeerNetwork`, реестр соседей (`Peer` реализует `PeerEndpoint`) и хранение ключей (`AgentKeys` реализует
  `IdentityKeys`, главный ключ — `AgentKeys::loadMain` из хранилища секретов);
- WebSocket-клиент (`WebsocketA2aChannel` реализует `A2aChannel`) — пакет получает его замыканием `connect`;
- незнакомые агенты, права агентов-участников, запуски, которые отвечают соседу, хранилище файлов, инструменты
  `peer_*` и команды владельца.

## Устройство

| Класс / каталог | Что делает |
|-----------------|------------|
| `src/AgentIdentity.php` | Ключ P-256: `fromPem`, `sign`, `verify`, `fingerprintOf` (`SHA256:` от DER). Данные подписей: запроса, ответа, карточки, обеих сторон рукопожатия; `audience` — адрес экземпляра в одном написании |
| `src/A2aClient.php` | Карточка (`card`, `provenCard`), `send`, `get`, `cancel`, `upload`, `download`; транспорт — по карточке соседа (`ws` или `http`); ключ для соседа — из `IdentityKeys` |
| `src/A2aSocket.php` | Один WebSocket: рукопожатие версии 2 (`open` у ведущего, `accepted` у ведомого), чтение кадров в своём файбере, запросы по `id`, уведомления, ответы на запросы другой стороны |
| `src/A2aChannel.php` | Интерфейс канала текстовых кадров: `send`, `receive`, `close`, `isClosed` |
| `src/A2aLinks.php` | Живые соединения, исходящие и входящие; поиск по отпечатку или имени, закрытие |
| `src/A2a.php` | Коды `-32050` и `-32051`, пределы файлов (20 МБ, 10 штук, тело 21 МБ), схема `a2a-file:`, текст сообщения, имя и тип файла, multipart |
| `src/A2aMoved.php` | У соседа нет такого входа (сменил транспорт): карточку читают заново |
| `src/PeerEndpoint.php` | Сосед глазами клиента: имя, адрес, закреплённый открытый ключ, карточка, имя ключа, которым представляться |
| `src/IdentityKeys.php` | Именованные ключи агента, `''` — главный |
| `src/Texts.php`, `src/functions.php`, `resources/texts.en.php` | Тексты ошибок по ключам, функция `t()`, английский каталог |
| `test/PeerTest.php` | Подпись и проверка, отказ не-P-256 ключу, общие помощники, транспорт по карточке, карточка без доказательства ключа |

## Решения

- **Агента узнают по ключу.** Каждый запрос и ответ подписан; токен входа только открывает дверь и не говорит, кто
  пришёл.
- **Ответ засчитывается только с закреплённым ключом соседа.** Самозванца по тому же адресу клиент не слушает;
  ответ привязан к запросу одноразовым числом.
- **Подпись называет адрес получателя** (`audience`). Запрос, подписанный для одного экземпляра, не годится на
  другом; рукопожатие, пересланное третьим экземпляром, не сходится ни с одной стороны.
- **Сосед добавляется только с доказанной карточкой.** `provenCard` просит подписать случайное число вместе с
  адресом: чужая или пересланная карточка не проходит.
- **Одно соединение в обе стороны.** Написать агенту можно по любому живому соединению с ним, кто бы его ни открыл;
  новое открывается, только если живого нет.
- **Файлы — раньше сообщения.** По умолчанию `POST /a2a/files` с multipart, в сообщении — ссылки `a2a-file:`; байты в
  кадрах — только по WebSocket по настройке приложения (`fileTransport`).
- **Несколько ключей.** Соседу показывают ключ, выбранный для него (`peerIdentity`), а не всегда главный.
- **Без потока статусов.** Ведущий опрашивает `GetTask`; конец задачи может прийти уведомлением по живому соединению.
- **Ошибки без токена.** Токен помечен `#[SensitiveParameter]`, в тексты неудач не попадает; ответ соседа читается
  не больше 1 МБ, таймауты — 30 с, файлы — 120 с.
- **Тексты снаружи.** `Texts::translateWith` получает переводчик при старте; без него — английский каталог. Пакет
  не зависит от `mercurius-i18n`.
- **Образец — A2A-плагин hermes** (`ref:` в `A2aClient`): найти соседа, вызвать, проверить; без потока. hermes
  ответы не подписывает — отступление.

## Проверки

- `composer check` — PHPUnit (`AsyncTestCase`), PHPStan уровня `max` по `src` и `test`, Psalm `errorLevel="1"` с
  плагином PHPUnit.
- CI — GitHub Actions, одна задача: PHP 8.2, `composer install` и `composer check`; без сети и секретов, изменения
  только в `**.md` проверку не запускают, лимит 10 минут.
- Клиент вместе с сервером проверяет Меркурий: тесты приложения и экземпляры на сервере проекта.
